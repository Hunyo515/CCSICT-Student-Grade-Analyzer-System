# University workflow

These requirements amend the supplied SRS. The brown interface and Segoe UI remain consistent across roles.

1. Admin maintains Subjects inside program folders, grouped by year and semester. Each program currently has one curriculum. The provided BSDSA curriculum remains imported. Subject forms use total units only; original source metadata and academic history remain preserved.
2. Admin activates the current school term in Settings. EnlistMe always uses this active term. **Prepare future classes** optionally allows preparing classes for a later term; students can enlist in those classes only after that term becomes active.
3. Admin opens Classes, selects the active or opened upcoming class term, chooses a curriculum subject and active faculty member, and enters a university section such as `BSDSA 1-1`. Subject program, year, and semester must match. Each subject/section/term has at most one responsible teacher. Classes may initially have no teacher. Admin can use **Assign faculty** on an unassigned class, or select the same subject/section/term in Create Class, to attach a professor without recreating the class or losing enrollments.
4. Students open **EnlistMe**, view all curriculum subjects matching their program, current year level, and current semester, and select the checkboxes beside the subjects they want. New subjects start unchecked, including subjects without an assigned professor. Selecting a subject creates or reuses the class for the student’s registered section and saves a real enrollment; faculty can be assigned later. **Enroll selected subjects** enrolls only checked available subjects. Existing enrollments are shown checked and disabled. Repeat submissions never duplicate enrollment or remove existing subjects or grades. Missing enrollments in published/submitted classes require administrator assistance. Prerequisite text is advisory. Enrollment codes and admin roster enrollment are retired.
5. Enlistment saves section membership for the current term and preserves the student profile and historical enrollments. A stale page cannot enroll into a term after it becomes historical. Dashboard term filters do not change the EnlistMe target.
6. Faculty open My Classes, choose one semester, then open a subject/section gradebook. Grading Settings allows custom components totaling 100% and activities within each component totaling 100%. Activity scores are normalized by their highest possible score, weighted within the component, then weighted into the semester grade. The worksheet shows raw totals, percentages, weighted scores, semester percentage, and the ISU numerical equivalent. Faculty enter/import scores and publish validated grades. Existing published classes keep their prior grading model. Students see only published results. Teachers reopen a class explicitly before correction; drafts remain private.

The header school-term selector is a read filter, including **All school terms**. It never activates a term. Student ranks require one selected term and use that term's recorded section membership when available. Historical/all-term views preserve published-grade privacy. Grade editing remains restricted to the active term.

# Accounts

- New faculty accounts receive a generated unique faculty ID (`FAC-XXXXXXXX`), used as a record identifier, and a password entered by the administrator. Faculty sign in using their institutional email address. Add Teacher collects first name, optional middle name, last name, institutional email, password, and confirmation.
- Admin-created student accounts receive a generated temporary password; their unique student ID (`23-2762`) is their username. First, optional middle, and last names are stored separately.
- Admin sees generated credentials once, through an encrypted delivery record that expires after 10 minutes. Share them privately. Admin-created student accounts must choose a new password before entering the portal. Faculty go directly to the dashboard with their registered password. The Add Teacher password fields offer a random password option on focus, or the administrator can type a password.
- Deleting a faculty account removes its login and faculty profile while keeping its classes, students, grades, and publication history. Classes become unassigned and can receive a replacement professor. Historical author names are saved independently of the deleted account.
- Passwords require at least eight characters, uppercase, lowercase, a digit, and a special character. The maximum is 72 UTF-8 bytes.
- Only administrators complete email OTP. Faculty sign in with their institutional email and password; email matching is case insensitive. Students can use their email address or Student ID and password. Self-registration creates an active account immediately. The student login field is labeled Username and accepts either identifier. Focusing Password or Confirm Password offers Generate random password; choosing it fills both fields. There is no separate suggestion section.
- Contact numbers use eleven digits beginning with `09`. Institutional faculty/student emails use a dotted name at `isu.edu.ph`, case insensitive. Sections follow program/year/group, such as `BSCS 1-2`.
- Existing names, IDs, usernames, and old section records are preserved. An administrator must verify corrections against real university records; the system does not invent replacement identities. Editing a student synchronizes their username with their corrected ID.

See LOCAL_SETUP.md for Gmail setup and SRS_COMPLIANCE.md for grading conventions. Oracle acceptance checks use rollback-only temporary academic records.

Admin > Faculty shows a selected-term assigned-class count. View opens teaching-load details in a desktop side panel or full-screen mobile panel. View Class opens a read-only class record and student roster. Unassigned faculty have an Assign Class link that preselects the faculty in Create Class. All-term filters include each class term in the details.

The faculty semester worksheet uses compact numbered assessment columns and a dedicated Highest Possible Score row. Each grading component has Total, PS (weighted percentage within the component), and WS (contribution to the semester percentage). Activity names and weights are shown by the assessment key and focused-cell help. The semester percentage and ISU numerical equivalent are calculated; SHS quarter weights/transmutation are not imposed.
